# 微信公众号 → Dify 知识库 导入流水线

把学校微信公众号的历史文章批量抓取、清洗后导入自建 Dify 知识库，供「科大精灵」智能体检索。**全程无需公众号后台权限**（微信文章页公开可访问）。

## 流程总览

```
链接清单        抓正文           清洗导出          OCR 图片文字       导入 Dify
links/xxx.txt → raw/xxx.json → output/xxx.md →（05 可选）→ Dify 数据集
   (01/手动)      (02)            (03)            (05)            (04)
```

## 环境准备

```bash
cd scripts/wechat-import
npm install          # 安装 cheerio（唯一依赖，Node 20+，项目 Node 24 可用）
```

## 第 1 步：收集文章链接

**推荐（手动，覆盖最全）**：在微信客户端打开公众号 → 查看历史消息 → 右上角「…」→ 复制文章链接，逐条粘贴到 `links/公众号名.txt`（每行一个 URL；可带 `\t标题\t日期` 便于归档，也可只放 URL）。

**辅助（自动）**：搜狗微信搜索可搜到该公众号近期文章：

```bash
node 01-fetch-links-sogou.mjs "中国科学技术大学" --pages=5
```

> 注意：搜狗反爬较严（可能出验证码），且只覆盖最近几个月，建议两种方式结合。多个公众号就建多个 txt 文件，文件名即公众号名。

## 第 2 步：批量抓取正文

```bash
node 02-fetch-articles.mjs                # 抓取 links/ 下所有公众号
node 02-fetch-articles.mjs --account 公众号名 --limit 20   # 单号限量试跑
```

- 输出 `raw/公众号名.json`，**断点续传**：重复运行自动跳过已抓取的 URL。
- 默认并发 3、每篇间隔约 1 秒；连续失败 8 次自动暂停 60 秒（防微信风控）。
- 抓取失败的记录会带 `error` 字段存入 json，清洗步骤自动跳过。

## 第 3 步：清洗并导出 Markdown

```bash
node 03-clean-export.mjs [--account 公众号名]
```

- 输出 `output/公众号名/日期-标题.md`（带公众号、标题、时间、原文链接的元数据头）与 `output/index.json`。
- 自动删除正文尾部的「引导关注 / 点赞在看 / 二维码 / 版权声明」等噪声段落；正文中间的报名二维码等信息**保留**。
- 正文转文本时移除图片；如需识别图片中的文字（通知/海报截图），见下方第 3.5 步。

## 第 3.5 步（可选）：识别文章图片中的文字

公众号通知常以图片/海报形式呈现文字，可用视觉模型 OCR 识别并回填到 Markdown，让 AI 能引用图片内容。**两种数据来源自动适配**：

```bash
node 05-ocr-images.mjs                        # 默认免费模型 PaddlePaddle/PaddleOCR-VL-1.5
node 05-ocr-images.mjs --model Qwen/Qwen3-VL-32B-Instruct   # 识别更稳（付费，约 1 元/百万 token）
```

- **流水线模式**（有 `raw/` 数据）：从正文 HTML 提取图片 URL（带微信防盗链下载），识别结果以「【文中图片文字】」小节追加到 md 文末。
- **md 模式**（外部工具 wechatDownload 等导出的 md，无 raw 数据）：直接从 md 提取图片引用——本地图片直接读取，URL 图片自动下载；识别结果插到对应图片下方（`> 【图片文字】…`）。
- 自动复用项目 `.env.local` 的硅基流动 key（`EMBEDDING_API_KEY`），无需额外配置；模型也可用 `OCR_MODEL` 环境变量指定。
- 默认模型为硅基流动**免费**的 PaddleOCR-VL-1.5（实测中文识别准确，零成本）；免费模型通常有速率限制，个人批量使用足够。
- 幂等：`ocr-log.json` 记录**成功**识别的图片，重跑不重复调用 API；失败的（超时/下载失败）不记录，重跑自动重试。
- **大批量建议分号跑**（如 `--account 蜗壳小道消息`），或开新终端窗口让脚本持续运行；中断后重跑同一命令即可续传。
- 注意：识别的是**图片中的文字**（通知、海报、表格截图），不是图片画面描述；纯装饰图（无文字）自动跳过。

## 第 4 步：导入 Dify 知识库

```bash
node 04-import-dify.mjs                    # 每个公众号自动建一个数据集并导入
node 04-import-dify.mjs --dataset-id xxx   # 导入到指定已有数据集
```

- 自动读取项目根 `.env.local` 的 `DIFY_BASE_URL` 与 `DIFY_KNOWLEDGE_API_KEY`（无需重复配置）。
- 每个公众号创建一个「公众号-xxx」数据集（`high_quality` 索引）；同名已存在则复用。
- 每篇文章一个文档，幂等导入（记录在 `dify-import-log.json`，重复运行自动跳过）。
- **支持直接导入外部工具导出的 Markdown**：把 md 文件按「公众号名」文件夹放进 `output/` 目录（如 `output/科科小黑板/xxx.md`），即使没有 `index.json` 也会自动扫描导入，无需先跑 02/03。
- 结束后会打印新数据集 ID，**把它追加到 `.env.local` 的 `DATASET_IDS`（逗号分隔）并重启 dev 服务**，智能体即可检索新内容。

## 第 5 步：验证

1. Dify 后台 → 知识库 → 新数据集 → 「召回测试」，输入典型问题看相似度与片段。
2. 重启项目后在智能体里问几个真实问题（如「××通知什么时候截止」），确认回答引用了公众号内容。

## 注意事项

- **合规**：内容仅用于校内知识库建设，注意版权与内部信息管理；建议只收录公开发布的信息。
- **风控**：单 IP 高频抓取可能触发微信验证；如果被风控，降低并发（改 `02` 脚本头部 `CONCURRENCY` / `INTERVAL_MS`）或分时段运行。
- **覆盖不全**：无后台权限时拿不到公众号全部历史文章（微信不开放全量列表），链接收集多少就入库多少；可持续用 01 + 手动方式增量补充。
- **已抓数据可复用**：`raw/`、`output/`、`dify-import-log.json` 都在本地，换 Dify 环境时直接重跑 04 即可。
