# 智能体增强：主动澄清 + 文件操作与代码执行

**日期**：2026-08-20
**状态**：已批准
**决策人**：何龙麒安

## 一、背景

校园AI助手（已合并 main 与 知识库构建 分支并完成重构）目前是一问一答的 RAG 问答系统。本次增强目标：使其成为功能更完善的智能体——

1. **主动澄清**：像 Claude 一样，信息不足或需求模糊时主动向用户提问确认需求
2. **文件操作与代码执行**：操作用户指定目录的文件（读取、修改），并能运行代码

## 二、已确认的关键决策

| 决策点 | 选择 |
|---|---|
| 部署形态 | 本地/局域网（安全设计以"防呆 + 可回滚"为主，不引入登录鉴权） |
| 文件访问区域 | 用户指定任意目录，但必须经授权才能访问 |
| 代码执行形态 | 项目目录 + 执行脚本（模型写脚本到授权目录，再执行该脚本） |
| 澄清触发 | 模型自主判断 + 关键操作强制确认（工具层拦截，不依赖模型自觉） |
| 目录授权 UX | 聊天内授权确认卡片 + 侧栏授权目录管理（持久化 localStorage） |
| 执行语言 | Node.js 为主 + Python 可选（检测到可用时） |

## 三、功能一：主动澄清

纯 prompt 层实现，无新 API。系统 prompt 增加澄清指南，模型按三档自主判断：

| 场景 | 行为 |
|---|---|
| 简单校园问答（校历/班车/图书馆等） | 直接检索作答，不追问 |
| 检索无命中或需求模糊 | 提出 1 个具体澄清问题 |
| 文件/执行类需求 | 先澄清目标路径、预期产出，再动手 |

约束：
- 最多连续追问 2 次，第 3 次给出最佳猜测答案（防无限追问循环）
- 每次追问聚焦一个问题，不列问题清单
- 澄清问题具体化（如"你说的转专业是大一还是研一？"），避免"请补充更多信息"式空问

与功能二的衔接：危险操作（写文件/执行命令）不依赖模型自觉，由工具层强制拦截确认。

## 四、功能二：文件操作与代码执行

### 4.1 工具集（AI SDK tool 机制，定义于 lib/tools/）

| 工具 | 危险级别 | 行为 |
|---|---|---|
| `list_dir` | 只读 | 列目录一层（名称 + 大小 + 类型），直接执行 |
| `read_file` | 只读 | 读文件，>512KB 截断并提示，直接执行 |
| `write_file` | 写 | 强制用户确认后执行 |
| `execute_command` | 执行 | 强制用户确认后执行（确认卡显示完整命令与 cwd） |

### 4.2 安全设计（本地/局域网形态）

1. **授权目录**：模型只能访问用户授权过的目录。聊天内授权确认卡片 + 侧栏授权目录管理区（增删、持久化 localStorage），授权列表随每次请求传入
2. **路径锚定**：所有路径 `resolve` 后做前缀检查，`../` 逃逸直接拒绝（`lib/tools/sandbox.ts` 纯函数，可单测）
3. **执行约束**：60s 超时、stdout/stderr 截断 64KB、无交互输入、cwd 限定在授权目录内
4. **确认卡片**：显示完整命令/文件路径，允许/拒绝二选一；拒绝则模型收到"用户拒绝"反馈继续对话

### 4.3 确认协议（无状态 HTTP 下的 Claude Code 式循环）

```
用户消息 → /api/chat
  → 检索 → streamText（带工具）
  → 模型流式回答；调用只读工具直接执行回填
  → 调用危险工具 → 拦截，随流返回 pending_tool_call 元数据
  → 前端渲染确认卡片（消息内，持久化到 localStorage）
  → 用户点允许/拒绝 → 前端回传 tool result 作为新消息
  → /api/chat 识别确认消息 → 执行工具 → 结果注入历史 → 继续生成
```

每步一次无状态 HTTP 请求，天然兼容现有 TextStreamChatTransport + localStorage 架构。

AI SDK v7 工具拦截细节实现时先查 node_modules/next 与 ai 包文档；若无优雅拦截 API，退路：`execute` 内抛 PendingApproval 异常，由 route catch 统一处理为 pending_tool_call 元数据。

### 4.4 前端新增

- `ToolApprovalCard` 组件：危险工具确认卡片（允许/拒绝）
- 侧栏授权目录管理区
- 消息 part 协议扩展：tool-request / tool-result 持久化到 localStorage

### 4.5 完整交互示例

"帮我统计这个文件夹里所有 txt 的字数"：
1. 模型澄清："文件夹的路径是什么？"
2. 用户提供路径 → 未授权 → 前端弹授权卡片 → 用户允许
3. `list_dir`/`read_file` 自动执行，模型报告发现 5 个 txt
4. 模型要 `write_file` 生成报告 → 确认卡片（路径 + 内容大小）→ 允许 → 写入
5. 模型总结结果

## 五、验证方案

1. sandbox 路径逃逸单测（`../`、绝对路径穿越、符号链接）—— 全部拒绝
2. curl 模拟多轮：澄清 → 授权 → 执行 → 生成报告的完整链路
3. dev server 手工走查（真实浏览器）

## 六、实施顺序

3. 前端：授权卡片、侧栏授权管理、确认卡片、消息协议扩展
4. prompt 澄清指南 + 澄清行为验证
5. 全链路验证
